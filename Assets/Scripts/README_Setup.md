# Emberpath — Step 1: Movement & Combat Vertical Slice

This is the setup guide for the first playable slice: run, double jump, dash and
a melee attack with hit feedback (knockback, hitstop, flash) against a dummy
enemy. Everything uses **placeholder visuals** (flat coloured squares generated
at runtime) — no final art.

> Engine: **Unity 6 LTS** (`6000.0.x`), **2D / URP**. The project was scaffolded
> as files in the repo. The first time you open it, Unity will import assets,
> resolve packages and may offer to upgrade the editor version — that is normal.

---

## 1. Open & play

1. Add this folder as a project in **Unity Hub** and open it with a Unity 6 LTS
   editor (`6000.0.x`). Let it finish importing and compiling.
2. Open `Assets/Scenes/TestArena.unity`.
3. Press **Play**. The arena (platforms, player, two dummy enemies, camera) is
   built procedurally on start by `TestArenaBootstrap`, so the scene looks almost
   empty in edit mode — that is expected. The console prints the control list on
   start.

If the scene ever gets out of sync, use the menu **Emberpath ▸ Create or Reset
Test Scene** to regenerate it.

## 2. Controls (keyboard / mouse for desktop testing)

| Action        | Keys                                  |
|---------------|---------------------------------------|
| Move          | `A` / `D` or `←` / `→`                |
| Jump          | `Space` / `W` / `↑` (double jump in air) |
| Dash          | `Left Shift` / `K`                    |
| Attack        | `J` / Left Mouse Button               |

Touch controls for iOS are a later step; this slice is wired for the **legacy
Input Manager** so it runs on a fresh project with zero input setup.

## 3. What you should see / test

- **Run** with acceleration, with a snappier fall (gravity is heavier on the way
  down). Coyote time + jump buffering make jumps forgiving.
- **Double jump**: one extra jump in the air.
- **Dash**: a quick horizontal burst with a cooldown; ignores gravity briefly.
- **Attack**: opens a hitbox in front of the player. Hitting a dummy applies
  **knockback**, a brief **hitstop** (whole-game freeze, ~0.08 s) and a white
  **flash**. The dummy has 3 HP, fades out on death, and respawns after 1.5 s so
  you can keep testing.

## 4. Script overview (`Assets/Scripts/`)

| File | Role |
|------|------|
| `Core/IDamageable.cs` | `IDamageable` interface + `DamageInfo` struct shared by attacker and victim. |
| `Core/Hitstop.cs` | Self-bootstrapping global hit-freeze helper (`Hitstop.Freeze(seconds)`). |
| `Core/PlaceholderSprites.cs` | Generates a 1×1 white square sprite at runtime (no art assets needed). |
| `Core/TestArenaBootstrap.cs` | Builds the whole test arena (camera, platforms, player, enemies) on `Awake`. |
| `Player/PlayerController.cs` | Run / double jump / dash, ground check, coyote time, jump buffer. |
| `Player/PlayerCombat.cs` | Melee hitbox (`OverlapBox`), damage + knockback, triggers hitstop on a clean hit. |
| `Enemy/DummyEnemy.cs` | Punching-bag `IDamageable`: health, knockback, flash, i-frames, respawn. |
| `Editor/TestArenaBuilder.cs` | Editor menu to (re)create the test scene. |

All gameplay code lives under the `Emberpath.*` namespaces. The combat code talks
to enemies only through `IDamageable`, so new enemy types just implement that
interface.

## 5. Tuning

Select the spawned **Player** at runtime (or tweak the defaults in
`PlayerController` / `PlayerCombat`) to adjust feel: `moveSpeed`, `jumpForce`,
`extraJumps`, `dashSpeed`/`dashDuration`/`dashCooldown`, `coyoteTime`,
`jumpBufferTime`, and on combat `damage`, `knockbackForce`, `hitboxSize`,
`hitstopDuration`. `DummyEnemy` exposes `maxHealth`, `flashColor`,
`knockbackRecovery` and `respawnDelay`.

## 6. Important notes (read once)

This project skeleton was authored **without running the Unity Editor**, so a few
things are worth a quick check on first open:

- **URP**: the Universal Render Pipeline package is included, but no URP asset is
  assigned as the active pipeline yet, so the slice renders under the **Built-in**
  pipeline by default. The flat-square placeholders look identical either way. To
  switch to URP for real: `Assets ▸ Create ▸ Rendering ▸ URP Asset (with 2D
  Renderer)`, then assign it under **Project Settings ▸ Graphics** (and the active
  Quality level). This is a one-time, one-click follow-up.
- **Input**: `Active Input Handling` is set to the legacy **Input Manager**
  (`Project Settings ▸ Player`). If you later adopt the new Input System for touch
  controls, switch it to *Both* and install the Input System package.
- **Ground layer**: a user layer named **`Ground`** (index 6) is defined in
  `Tags & Layers`; platforms are placed on it and the player's ground check only
  tests that layer, so the player never detects its own collider as ground.
- The `Library/` folder is intentionally git-ignored and is regenerated by Unity
  on first open.

## 7. Continuous Integration

GitHub Actions compiles the project and runs the EditMode smoke test on every
push (`.github/workflows/ci.yml`), so script/compile errors are caught
automatically. One-time license setup (Unity Personal): see
[`.github/CI_SETUP.md`](../../.github/CI_SETUP.md). A small EditMode test lives in
`Assets/Tests/EditMode/`.
